Authentication

Rewake API authentication relies on Bearer tokens and an optional origin/referer check.

Tokens

Token

Description

Access

ADMIN_TOKEN

Administrator token

All routes; bypasses the origin check

HELLOPRO_TOKEN

Dedicated HelloPro token

Only /hellopro/* routes

MACHINIO_TOKEN

Dedicated Machinio token

Only /machinio/* routes

APP_TOKEN

Token dedicated to the internal app

Only /internal/* routes

AIRTABLE_AUTOMATION_TOKEN

Token sent by Airtable automations (≠ AIRTABLE_TOKEN, which the API sends to Airtable)

Only /internal/scripts/* routes

[!WARNING] Tokens must be set in .env and must never be committed.

Allowed origins

The API accepts requests from the following domains when the origin check is enabled, using either the Origin or Referer header (ALLOWED_ORIGINS in api/utils/auth.py):

  • https://app.rewake.fr

  • https://sav.rewake.fr

  • https://info.rewake.fr

CORS (api/main.py), however, only allows app.rewake.fr and sav.rewake.fr.

Public routes (/health/, /metrics, /invoice/get, /pdf/{filename}, /formulaire/photos/*) require neither a token nor an origin (see routes).

Verification logic

With ADMIN_TOKEN

Automatic access to all routes, without an origin/referer check.

Rules by route

Route

Origin check

/hellopro/*

❌ No (HELLOPRO_TOKEN required only)

/machinio/*

❌ No (MACHINIO_TOKEN required only)

/internal/*

✅ Yes (APP_TOKEN and a valid origin/referer)

/internal/scripts/*

✅ Yes with APP_TOKEN; ❌ No with AIRTABLE_AUTOMATION_TOKEN

[!IMPORTANT] ADMIN_TOKEN always bypasses the origin check on every route.

When an origin is checked, the check happens before the token check: a request without a valid origin receives 403 Access denied: invalid domain, regardless of its token; with a valid origin but an invalid token, it receives 403 Access denied: invalid token. If a token’s environment variable is not set, only ADMIN_TOKEN grants access to the corresponding routes.

Request examples

Token only (ADMIN_TOKEN)

curl -H "Authorization: Bearer ADMIN_TOKEN" \
     http://localhost:3002/internal/logs/
# ✅ 200 - Accès autorisé (contourne l'origine)

APP_TOKEN + Origin

curl -H "Authorization: Bearer APP_TOKEN" \
     -H "Origin: https://app.rewake.fr" \
     http://localhost:3002/internal/logs/
# ✅ 200 - Token valide + origine autorisée

APP_TOKEN without Origin

curl -H "Authorization: Bearer APP_TOKEN" \
     http://localhost:3002/internal/logs/
# ❌ 403 - Origin/Referer manquant

HELLOPRO_TOKEN (no origin check)

curl -H "Authorization: Bearer HELLOPRO_TOKEN" \
     http://localhost:3002/hellopro/csv/
# ✅ 200 - Token valide, l'origine n'est pas vérifiée

Airtable automation (AIRTABLE_AUTOMATION_TOKEN)

Airtable automations run on Airtable’s servers, without an Origin header. The dedicated AIRTABLE_AUTOMATION_TOKEN is accepted on /internal/scripts/* only.

curl -X POST -H "Authorization: Bearer AIRTABLE_AUTOMATION_TOKEN" \
     "http://localhost:3002/internal/scripts/create_product_shopify/run?record_id=recXXX"
# ✅ 200 - {"task_id": ..., "status": "queued", ...}

curl -H "Authorization: Bearer AIRTABLE_AUTOMATION_TOKEN" \
     http://localhost:3002/internal/backups/
# ❌ 403 - hors de /internal/scripts/*

Origin without a token

curl -H "Origin: https://app.rewake.fr" \
     http://localhost:3002/internal/logs/
# ❌ 403 - Token manquant
