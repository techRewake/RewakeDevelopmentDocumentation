Rewake API

The back-end API for Rewake – internal tooling (used by the app.rewake.fr intranet app) and external integrations (HelloPro, Machinio), served at api.rewake.fr.

This documentation set is new (see Development for why and what’s still missing); the API and its endpoints existed and were in production well before it.

Reference

  • Routes – every endpoint, its access rules, and example responses.

  • Authentication – the token/origin model behind those access rules.

  • Architecture – how the project fits together, including the Celery/Redis queued tasks (scripts, OCR, AI research).

  • Operations – configuration, deployment, and logging.

  • Development – environment setup, Airtable/Shopify dev credentials, and the scripts/ dev tooling.

  • Scripts – what each registered script does, on demand or scheduled.

  • Catalog model: Model, Variation, Unit – how Model, Variation and units are linked, how they become a Shopify product, and how to create a new one.

  • Catalog intake: receiving batches to Airtable – the /internal/catalog routes behind the app’s receiving workflow (draft push, validation, units, reprises, label OCR, reference suggestion) and commercial review (review queue, model sheet, verification), plus the central AI service behind /internal/ai.
