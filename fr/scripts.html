Scripts

Enregistrés dans api/scripts/registry.py, ils sont tous exécutables à la demande via POST /internal/scripts/{name}/run (voir Architecture). Les deux scripts planifiés s’exécutent aussi automatiquement via beat ; les calendriers ci-dessous sont les valeurs par défaut, configurables dans .env (voir Operations). Historique : GET /internal/scripts/{name}/runs ; progression en direct : GET /internal/scripts/{name}/current.

  • Update Product – synchronise une annonce Shopify existante depuis Airtable (à la demande ; accepte l’identifiant d’une Variation ou d’un Model, qui désignent le même produit ; code natif porté en processus depuis un sous-processus d’un projet voisin).

  • Create Product Shopify – crée une nouvelle annonce Shopify à partir d’un Model Airtable (à la demande ; code natif – l’autre script de ce registre qui écrit dans Shopify, avec update_product).

  • Shopify Catalog Reconciliation – vérifie que Shopify reflète le catalogue Airtable commercialisable (toutes les heures). Remplace l’ancien script distinct verification_shopify, qui effectuait le même type de comparaison et a été supprimé.

  • Airtable Catalog Stats – statistiques sur la structure du catalogue, indépendantes de Shopify (chaque jour à 20 h 42, heure de Paris).
